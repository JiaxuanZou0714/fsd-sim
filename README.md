# FSD 城市自动驾驶模拟器 · 巴黎星形广场

在浏览器中运行的自动驾驶演示。路网来自 OpenStreetMap，范围为巴黎戴高乐广场（凯旋门）周边约 1.2 × 1.2 公里：12 条大道汇入的四车道环岛、多车道林荫大道、大量单行道和不规则路口。车辆通过采样轨迹优化完成决策，车辆不在车道上时使用 Hybrid A* 在自由空间中规划。

## 运行

需要 Node.js 20 或更高版本。

```bash
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173
npm run build      # 类型检查并构建到 dist/
npm test           # 无界面的仿真测试
```

地址后加 `#play` 可跳过开场说明。

## 操作

| 按键 | 功能 |
| --- | --- |
| 点击小地图或路面 | 设置目的地 |
| `F` | 启用 / 退出 FSD |
| `W` `A` `S` `D` 或方向键，`空格` | 手动驾驶与制动；FSD 启用时按下即视为接管 |
| `J` / `B` / `K` | 在前方生成横穿行人 / 违停车辆 / 自行车 |
| `O` | 把车辆放到非道路区域（庭院、人行道、广场） |
| `V` | 把车辆放在单行道上，方向与车流相反 |
| `R` | 随机目的地 |
| `C` | 切换视角（跟随、近距、俯视） |
| `T` | 模拟速度 1× / 2× / 4× |
| `P` | 暂停 |

右侧面板可切换候选轨迹与预测轨迹的显示，调整车辆和行人数量。左侧规划器面板显示当前模式、可行轨迹数与评估轨迹数、求解耗时，以及限制车速的约束来源。

## 地图数据

`tools/build-map.mjs` 将 Overpass API 导出的原始数据（`tools/osm-etoile.raw.json`）转换为局部米制坐标，并在地图边界处截断道路，截断点作为车辆的进出口。输出文件为 `src/data/paris-etoile.json`。

`src/sim/map/network.ts` 在运行时由该文件构建车道级路网：

| 内容 | 处理方式 |
| --- | --- |
| 车道 | 按 `lanes`、`lanes:forward`、`lanes:backward` 和道路等级确定每个方向的车道数，按偏移生成车道中心线 |
| 路口 | 按相交道路宽度和夹角计算各路段的截断距离，生成路口轮廓 |
| 转向连接 | 按转向角区分直行、左转、右转；左转从最内侧车道、右转从最外侧车道出发，环岛出口从外侧车道出发 |
| 冲突点 | 同一路口内来自不同进口道的连接线距离小于 2.2 米时记为冲突点 |
| 通行权 | 环岛内车辆优先，其次按道路等级和转向类型；信号灯路口只比较转向类型 |
| 信号灯 | 距信号灯节点 28 米内的路口受控；相距 36 米内的路口合并为一个控制器，按进口方向分相位 |
| 人行横道 | 映射到最近路段，信号灯附近的横道随所在方向的红灯放行 |
| 栅格 | 1 米分辨率的建筑物占用与距离场、路面范围，用于自由空间规划与碰撞检测 |

## 交通参与者

| 类型 | 行为 |
| --- | --- |
| 轿车、SUV、出租车、厢式货车、公交车、卡车、摩托车、自行车 | 尺寸、加速度、期望车速和车头时距各不相同 |
| 驾驶风格 | 普通、激进（车头时距短、接受更小的变道间隙、主动超车）、谨慎 |
| 公交车 | 在主干道最外侧车道的站点停靠 |
| 出租车、厢式货车 | 随机临时停车载客或违停卸货，停车时打开双闪 |
| 自行车 | 靠近路缘骑行 |
| 行人 | 在横道处等待信号或车流间隙后通过，部分行人接受更小的间隙（1.6 秒，其余为 4.5 秒）；另有沿人行道行走的行人和中途横穿的行人 |

其他车辆在路口按冲突点、通行权和到达时间决定是否让行，等待超过 9 秒后放弃让行。

## 自动驾驶算法

决策部分尽量不使用针对具体场景的规则。变道、绕行、让行、跟车和停车都由同一个代价函数比较候选轨迹后得出。

### 处理流程

| 阶段 | 方法 | 代码 |
| --- | --- | --- |
| 定位 | 按位置与航向匹配车道或路口连接线；偏离后在参考线附近仍保持车道模式 | `ego.ts` |
| 路线规划 | 车道级 Dijkstra。变道是带代价和最小距离的边；搜索状态区分"从车道起点进入"和"变道进入"；目的地可从道路任一侧到达 | `planner/route.ts` |
| 参考线 | 把路线展开为连续折线，逐点记录同向车道左右边界、对向车道宽度、限速、信号停止线和路口范围 | `planner/reference.ts` |
| 预测 | 只使用可观测信息：位置、航向、速度、由速度变化估计的加速度、转向灯。车辆沿车道图外推，路口按转向灯选择连接线；行人按匀速外推 | `planner/prediction.ts` |
| 轨迹规划 | 采样轨迹优化，见下文 | `planner/lattice.ts` |
| 自由空间规划 | Hybrid A*，见下文 | `planner/hybridAstar.ts` |
| 控制 | 车道模式使用 Stanley 控制器加曲率前馈；自由空间模式使用前进和倒车通用的纯跟踪 | `ego.ts` |

### 采样轨迹优化

每 0.1 秒执行一次：

1. 在参考线的 Frenet 坐标系中生成横向路径。终点横向偏移包括参考车道、左右相邻同向车道、对向车道（仅当左侧没有同向车道时）和 ±0.6、±1.2 米的小幅偏移；每个偏移使用两种过渡长度，路径为按弧长参数化的五次多项式。
2. 生成纵向速度曲线：6 个目标车速各两种过渡时间（四次多项式）、12 个停车距离（五次多项式）和一条最大制动曲线。
3. 路径与速度曲线两两组合，每 0.25 秒采样一次，共 6 秒，按以下各项计算代价：

| 代价项 | 内容 |
| --- | --- |
| 碰撞 | 与预测位置的净距离小于安全裕量即不可行。裕量随预测时间增大；横穿和对向车辆的裕量大于同向车辆，行人的裕量最大 |
| 接近 | 净距离小于 1.6 米时按指数增加 |
| 跟车距离 | 与行进方向前方交通参与者的距离小于 2.4 米加车速乘 1.15 秒时增加；静止车辆为 4.5 米起，便于从旁驶出 |
| 信号灯 | 红灯时车头越过停止线即不可行；黄灯时 2 秒后越线的代价很高 |
| 横向加速度 | 超过 2.4 米每二次方秒时增加，超过 4.5 米每二次方秒时不可行 |
| 车速 | 与限速和弯道速度的差值平方；超速另计 |
| 进度 | 6 秒内行驶距离越长代价越低，以目的地为上限 |
| 走廊 | 偏离参考线的平方、进入对向车道、越过路缘、在路口内偏离连接线；靠近建筑物即不可行 |
| 舒适性 | 加加速度与加速度平方，急刹另计 |
| 连续性 | 与上一周期选择的横向偏移之差 |

4. 选择代价最低的可行轨迹；没有可行轨迹时，沿最晚发生接触的路径最大制动。

界面上的驾驶意图也由代价计算得出：在所选路径上找比所选速度曲线稍快一档的候选，它不可行的原因或最大的代价项就是当前的约束来源，例如"礼让行人"或"红灯，停车等待"。

### 自由空间规划

以下情况从车道模式切换到自由空间模式：

- 无法把车辆匹配到方向一致的车道，例如在庭院、人行道或广场上，或在单行道上逆向；
- 当前车道无法到达目的地；
- 前方静止车辆看起来是停驶状态，且等待超过 5 秒（打开双闪）或 10 秒（未打开双闪）；
- 前车静止超过 30 秒。

判断前车是停驶还是排队只使用可观测线索：双闪、前车前方是否还有静止车辆、前车是否正对红灯。

Hybrid A* 在 (x, y, 航向) 空间搜索，航向分 72 档。每步前进或倒车 1.6 米，共 5 档曲率。代价计入倒车、换向、转向和驶离路面，障碍物为建筑物距离场和静止车辆。搜索目标是周边车道上方向与车道一致的位姿，因此掉头和三点调头会作为搜索结果出现。执行过程中，前方有交通参与者时停车等待，受阻超过 4 秒重新搜索。车辆对齐目标车道后切回车道模式。

## 测试

`npm test` 运行 `tests/sim.test.ts`：

- 路网规模、冲突点、信号控制器、横道和连通核心；
- 任意两条核心车道之间的路线，以及目的地在车辆后方时的绕行；
- 中途横穿的行人前制动避让；
- 越过本车道上的停驶车辆；
- 从非道路位置出发（3 个种子）和在单行道上逆向出发（2 个种子）后回到车道；
- 在混合交通和随机事件下行驶 4 分钟（3 个种子），无碰撞且累计到达至少 3 次；
- 手动接管计为一次接管。

`tests/sweep.test.ts` 用于批量压力测试，仅在设置 `SEEDS` 环境变量时运行，例如 `SEEDS=1,2,3 DUR=300 npx vitest run tests/sweep.test.ts`，输出到达、碰撞、自由空间脱困和最长停滞时间。

## 局限

- 感知直接读取仿真中的真实状态，没有传感器噪声和遮挡。
- 其他车辆和行人由规则驱动。
- 路网只包含车行道，没有停车场内部通道和地下道路；人行道位置按道路宽度推算。
- 代价函数的权重为人工设定。
